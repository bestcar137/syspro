## 기본 형식과 핵심 태그

`/** ... */`는 문서화 주석입니다. `@` 뒤에는 정해진 Doxygen 명령어를 적습니다.
`@brief`와 `\brief`는 같은 명령입니다. 주석은 프로그램의 실행 동작을 바꾸지 않습니다.

```c
/**
 * @brief 함수의 역할을 짧게 설명합니다.
 *
 * 필요한 경우 여기에 상세 설명을 적습니다.
 *
 * @param value 입력값의 의미입니다.
 * @return 반환값의 의미입니다.
 */
int process(int value);
```

| 태그          | 의미             | 언제 쓰나                                                    |
|---------------|------------------|--------------------------------------------------------------|
| `@brief`      | 짧은 요약        | 함수·타입 등의 역할을 간단히 설명                            |
| `@details`    | 상세 설명        | 동작 과정 등을 별도로 설명. 빈 줄 뒤에 일반 문장으로 써도 됨 |
| `@param`      | 매개변수 설명    | 매개변수별 의미 설명                                         |
| `@return`     | 반환값 설명      | 반환값의 전체적인 의미 설명                                  |
| `@retval`     | 특정 반환값 설명 | 값마다 성공·실패 등의 의미를 구분                            |
| `@note`       | 참고사항         | 부가 정보 전달                                               |
| `@warning`    | 경고             | 잘못 사용했을 때 발생하는 문제 안내                          |
| `@see`, `@sa` | 관련 항목        | 연관된 함수·문서 안내                                        |

## 매개변수와 반환값

| 작성 형식                  | 의미                                    |
|----------------------------|-----------------------------------------|
| `@param[in] name 설명`     | 함수가 읽는 입력값                      |
| `@param[out] name 설명`    | 포인터 등을 통해 결과를 저장하는 출력값 |
| `@param[in,out] name 설명` | 기존 값을 읽고 수정하는 값              |
| `@return 설명`             | 반환값의 전반적인 의미                  |
| `@retval 0 설명`           | 반환값이 0일 때의 의미                  |
| `@retval -1 설명`          | 반환값이 -1일 때의 의미                 |
| `@pre`                     | 호출 전에 충족해야 할 조건              |
| `@post`                    | 실행 후 보장되는 상태                   |
| `@invariant`               | 유지되어야 하는 불변 조건               |

```c
/**
 * @brief 정수 하나를 읽습니다.
 * @param[out] result 읽은 값을 저장할 위치입니다.
 * @retval 0 읽기에 성공했습니다.
 * @retval -1 읽기에 실패했습니다.
 */
int read_value(int *result);
```

- `@param` 뒤의 이름은 실제 매개변수명과 일치시킵니다.
- `[out]`은 함수의 반환값이 아니라 매개변수를 통한 출력을 뜻합니다.
- `void` 반환형에는 보통 `@return`을 쓰지 않습니다.
- `@return`과 `@retval`은 필요에 맞게 선택하거나 함께 사용할 수 있습니다.
- 주석에 적은 조건이나 결과는 실제 구현과 일치해야 합니다.

## 주의사항과 작업 기록

| 태그                  | 의미·용도                   |
|-----------------------|-----------------------------|
| `@note`               | 참고 정보                   |
| `@warning`            | 사용 시 위험이나 제약       |
| `@attention`          | 특별히 주목할 사항          |
| `@important`          | 중요한 사항 강조            |
| `@remark`, `@remarks` | 설계 의도 등의 보충 설명    |
| `@todo`               | 앞으로 해야 할 작업         |
| `@bug`                | 알려진 버그                 |
| `@deprecated`         | 사용 중단 권고 및 대체 방법 |
| `@test`               | 테스트 방법이나 검증 항목   |
| `@see`, `@sa`         | 관련 함수나 문서            |

```c
/**
 * @brief 데이터를 버퍼에 저장합니다.
 * @param[out] buffer 결과를 저장할 버퍼입니다.
 * @warning 호출 전에 충분한 버퍼 공간을 확보해야 합니다.
 * @todo 버퍼 크기 검사 기능을 추가합니다.
 */
```

## 파일 정보

| 태그                  | 용도               |
|-----------------------|--------------------|
| `@file`               | 파일 전체 설명     |
| `@author`, `@authors` | 작성자             |
| `@date`               | 날짜               |
| `@version`            | 버전 정보          |
| `@since`              | 기능이 도입된 버전 |
| `@copyright`          | 저작권 정보        |

```c
/**
 * @file exit_handler.c
 * @brief 종료 처리기 등록과 호출 순서를 확인하는 예제입니다.
 * @author bestc
 */
```

AI 프롬프트에서 특정 태그를 금지하는 것은 생성 형식에 관한 선택입니다. 
해당 태그가 잘못된 명령이라는 뜻은 아닙니다.

## 서식과 코드 예시

| 태그                         | 용도                                |
|------------------------------|-------------------------------------|
| `@code` / `@endcode`         | 여러 줄 코드 블록                   |
| `@c 단어`                    | 짧은 코드·식별자를 코드 글꼴로 표시 |
| `@p 이름`                    | 매개변수명 등을 코드 글꼴로 표시    |
| `@b 단어`                    | 굵게 표시                           |
| `@a`, `@e`, `@em`            | 단어 강조                           |
| `@n`                         | 줄바꿈                              |
| `@li`                        | 목록 항목                           |
| `@par 제목`                  | 제목이 있는 문단                    |
| `@verbatim` / `@endverbatim` | 내용을 해석하지 않고 그대로 표시    |
| `@parblock` / `@endparblock` | 한 설명 항목에 여러 문단 포함       |

```c
/**
 * @brief 종료 처리기 등록 예입니다.
 * @par 사용 예
 * @code
 * atexit(exit_handler1);
 * @endcode
 */
```

## 현재 실습에 적용하기

### atexit의 설명

`@exit`은 기본 Doxygen 태그가 아닙니다. 종료 처리기 설명은 `@brief`로 적습니다.
`atexit`의 선언에서 반환형은 `void`가 아니라 `int`입니다.

```c
int atexit(void (*func)(void));
```

- 성공 시 0, 실패 시 0이 아닌 값을 반환합니다.
- 등록하는 함수는 인수와 반환값이 없는 `void func(void)` 형태입니다.
- 등록된 종료 처리기는 등록 순서의 역순으로 호출됩니다.

```c
/**
 * @brief 프로그램 정상 종료 시 실행할 종료 처리기입니다.
 */
static void exit_handler1(void);
```

### 환경 변수 출력 프로그램

```c
/**
 * @brief 환경 변수 HOME, SHELL, PATH의 값을 출력합니다.
 *
 * getenv로 각 값을 조회하여 표준 출력에 출력합니다.
 * 마지막에 exit(0)을 호출하여 종료 상태 0으로 종료합니다.
 *
 * @param argc 명령행 인수의 개수입니다. 이 함수에서는 사용하지 않습니다.
 * @param argv 명령행 인수 문자열을 가리키는 포인터 배열입니다.
 *             이 함수에서는 사용하지 않습니다.
 */
```

이 설명은 실제 코드가 위 동작을 구현했을 때 사용합니다. `getenv`가 NULL을 반환하는 경우를 검사하지 않는 코드에 오류 처리를 수행한다고 적으면 안 됩니다.

## 자주 헷갈리는 점

1. **태그는 임의로 만들지 않습니다.** 기본 태그 `@exit`은 없습니다. 사용자 정의 별칭은 별도 설정이 필요합니다.
2. **주석에는 실제 구현만 설명합니다.** 없는 오류 처리나 성공 보장을 AI가 추가했는지 확인합니다.
3. **return과 exit는 구분합니다.** `return 0;`은 함수에서 값을 반환하고, `exit(0);`은 프로그램을 종료합니다. main의 최초 호출에서 `return 0;`을 실행하는 것도 정상
   종료로 이어지지만 동작을 설명할 때는 구분합니다.
4. **main 끝 도달은 별도 규칙이 있습니다.** C99 이후 main 끝에 도달하면 0을 반환한 것과 같습니다. exit (0)이 없다고 반드시 종료 처리가 누락된 것은 아닙니다.
5. **argv의 정확한 타입 설명은 문자 포인터 배열입니다.** 함수 매개변수의 `char *argv[]`는 `char **argv`로 조정됩니다.
6. **AI 생성 결과는 매번 달라질 수 있습니다.** 영어·한국어 모두 정확성을 확인해야 합니다. 기존 문장의 의미를 유지하려면 해당 원문 자체를 번역 입력으로 제공합니다.
7. **CLion 표시와 Doxygen 전체 기능은 다를 수 있습니다.** 모든 태그가 IDE에서 동일하게 표시되거나 자동완성되는 것은 아닙니다.

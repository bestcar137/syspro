# 과제 3 — fork ()의 수행 역할

## 출력

부모의 PID를 P, 새로 생성된 자식의 PID를 C라고 하면 다음과 같다.

```text
[1] =P
[2] = C, P
```

실제 WSL 실행 결과 (`execution.txt`):

```text
[1] =43327
[2] = 43328, 43327
```

## 해설

1. `[1]`은 `fork()` 호출 전에 실행되므로 기존 부모 프로세스가 자신의 PID를 출력한다.
2. `fork()`는 현재 프로세스를 바탕으로 새 자식 프로세스를 만든다. 부모와 자식 모두 `fork()` 호출이 끝난 지점부터 실행을 계속하며 `main()`의 처음부터 다시 시작하지 않는다.
3. 부모의 `fork()` 반환값은 자식 PID, 자식의 반환값은 0이다. 실패하면 부모에게 -1을 반환하며 자식은 생성되지 않는다.
4. `if (pid == 0)` 조건은 자식에서만 참이다. 따라서 `[2]`는 자식만 출력하며 `getpid()`는 C, `getppid()`는 P를 반환한다.
5. `[1]`의 값과 `[2]`의 두 번째 값이 같다는 점에서 부모·자식 관계를 확인할 수 있다. 두 프로세스는 서로 다른 PID와 별도의 주소 공간을 갖는다.
6. `sleep(1)`은 조건문 밖에 있으므로 부모와 자식이 모두 실행한다. 두 프로세스는 동시에 진행하므로 반드시 총 2초가 걸리는 것은 아니다.

## 원본 예제에 추가한 처리

`fork_example.c`는 PDF 29쪽의 핵심 출력과 `sleep(1)`을 유지하고 다음을 보완했다.

- `fork()` 실패를 검사한다.
- `fork()` 전 `fflush(stdout)`로 출력 버퍼를 비운다. 원본을 파일이나 파이프로 출력하면 버퍼에 남아 있던 `[1]` 문자열이 자식에도 복제되어 두 번 출력될 수 있다. 이는 `fork()`
  이전 코드를 두 번 실행해서 생기는 현상이 아니다.
- 부모에서 `waitpid()`로 자식을 기다리고 회수한다. 원본의 `sleep(1)`만으로는 부모가 먼저 종료하지 않는다고 보장할 수 없다. 추가된 대기로 자식이 출력할 때 부모가 살아 있도록 하고 좀비
  프로세스도 회수한다.

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic -o fork_example fork_example.c
./fork_example
```
